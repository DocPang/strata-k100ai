# 卡外 KV 容量扩展

单卡 64 GiB 显存里，KV 只占很小一部分（256K 上下文约 3.1 GiB），大头是全量专家驻留。真正的瓶颈是**并发长会话**：每个并发槽位都要一份完整 KV，槽位一多就必须从专家缓存里扣，decode 会明显掉速。

好消息是引擎自带两级"卡外"机制，不需要额外的分布式 KV 服务。

## 1. 引擎自带的两级存储

| 层级 | 参数 | 行为 |
|---|---|---|
| L2 内存 | `--conversation-cache-mib` / `--conversation-cache-slots` | 把不活跃的会话停在进程 RAM 里，下次请求自动恢复 |
| L3 文件 | `--slot-save-path DIR` | 通过 `POST /slots/0?action=save\|restore` 把会话存成文件、读回显存 |

L3 是**普通文件**，因此把 `--slot-save-path` 指向一个两卡都能看到的目录，就自然获得了跨卡共享——不需要任何额外协议。

推荐分层：

```
VRAM（正在生成的会话）
  ↓ conversation-cache（各卡自己的 RAM，自动，最快）
  ↓ tmpfs 共享目录（内存速度 + 跨卡共享）
  ↓ SSD 共享目录（大容量 + 重启不丢）
```

## 2. 实测数据

单会话状态实测约 **23.6 KB/token**（会话文件同时包含 QSA 的 KV、GDN 线性注意力状态和 MTP 草稿层，因此比只算 KV 的 12.4 KB/token 大一倍）。

| 上下文 | 会话文件 | 存盘 | 读回 | 重新 prefill |
|---|---:|---:|---:|---:|
| 26K | 611 MiB | 0.95 s（tmpfs）/ 1.35 s（磁盘） | 1.10 s（跨卡） | 17.7 s |
| 64K | ~1.5 GiB | ~3 s | ~3 s | ~45 s |
| 256K | ~6.0 GiB | ~12 s | ~12 s | ~312 s |

搬运吞吐实测约 **500–650 MB/s**。值得注意的是 tmpfs 与磁盘只差约 1.4 倍——瓶颈在引擎的数据搬运路径，不在存储介质（磁盘本身能跑 1.8 GB/s）。

跨卡测试（同一会话在一张卡上建立，在另一张卡上读回并继续）：**17.84 s → 1.09 s**。读回后的输出与重新计算**逐字节一致**（贪心解码 SHA 相同）。

## 3. 会话管理器

引擎的 L3 接口是手动的，需要一个薄层把"会话空闲就落盘、请求回来就读回"自动化。这一层放在网关闭和引擎之间，逐请求做：

1. 用 `sha1(model + 会话开头的消息)` 算出会话指纹。取"前导 system 消息 + 第一条真实消息"作为开头，因为后续轮次都是追加，这段前缀在整个会话生命周期里逐字节不变。
2. 如果该会话在最近 N 个（默认等于 `--conversation-cache-slots`）之内，直接透传——热会话交给引擎自己的 L2，零开销。
3. 否则先存走当前占着槽位的会话，再读回目标会话的存档（如果有），然后转发请求。
4. 空闲一段时间后自动把常驻会话落盘。
5. 后台任务在共享内存盘超过阈值时把最久未访问的会话下沉到 SSD。

两个必须注意的实现细节：

- 转发流式响应必须用 `read1()` 而不是 `read(n)`。`read(n)` 会阻塞到攒满 n 字节，会把逐 token 的 SSE 变成 64 KiB 一大段的突发。
- 上行到引擎的密钥要用引擎自己的，不要把调用方的网关密钥透传过去。

## 4. 收益与成本

在 18 个会话交错、每会话 3 轮（约 8K token）的负载上：

| 轮次 | 有会话管理 | 直连引擎 |
|---|---:|---:|
| 第 1 轮（冷启动） | 111.6 s | 102.8 s |
| 第 2 轮 | 24.7 s | 105.5 s |
| 第 3 轮 | 23.9 s | 114.8 s |
| 总计 | **160.2 s** | **323.1 s** |

单次会话切换的存盘成本约 **+0.49 s**，每次长尾回归节省约 **4.5 s**。**只要一个会话会被再次访问，成本就能赚回来**；对每个会话只问一次的一次性负载则是净亏。并发会话数不超过 `--conversation-cache-slots` 时，管理器完全不介入，成本为零。

## 5. 限制

- `--slot-save-path` 与 `--batch` **互斥**：并行请求共享控制线，会话文件会与请求交错，引擎会直接拒绝。要并发槽位就不能用文件层。
- 存/读期间占用引擎的 FIFO，其他请求排队等待（26K 约 1 秒，256K 约 12 秒）。
- 会话文件按 token 前缀恢复，与保存时的模型权重、KV 格式和注意力布局必须兼容；换权重后旧文件不能复用。
- tmpfs 掉电丢失，需要持久化时依赖 SSD 目录。
