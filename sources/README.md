# 源码快照（按版本分目录）

每个发布版本一个目录，目录名与 `engines/strata/<id>` 一致，便于把源码、补丁、清单和二进制一一对应。

| 版本 | 引擎 SHA-256 | 目录 | 内容 |
| --- | --- | --- | --- |
| v0.1.0-rc.6（当前） | `43002a72…` | [`xxs-20261016-gold/`](xxs-20261016-gold/) | 增量源码 7 文件 + 补丁链 4 个 + 相对上游的累计差异 |
| v0.1.0-rc.5 及更早 | — | 见 `engines/strata/<id>/patches/` | 以补丁形式保存，未单独展开成目录 |

## 约定

1. **一个版本一个目录**，只放该版本相对父版本的增量文件，不复制整棵引擎树（避免仓库随版本线性膨胀）。
2. 目录内必须有 `manifest.json`：逐文件 `sha256` + 字节数、引擎二进制 `sha256`、父版本、上游参考提交、补丁应用顺序。
3. 目录内必须有 `README.md`：说明"这个版本改了什么、怎么从上游复现、验证到什么程度"。
4. `vs-upstream-<commit>.diff` 是**该目录所涉文件**相对上游的累计差异，便于 review；它不等于整棵引擎树的差异。
5. 二进制不进 Git，通过 GitHub Release 分发；`sources/` 只承载源码与补丁。
6. **快照不可变**：已发布版本的源码文件不回头修改（否则无法再自证与某个二进制对应）；缺陷、不可达路径和待修项写进该版本的 `KNOWN_ISSUES.md`，修复进下一个版本目录。

## 复现路径

```
上游 Niko1221/Strata @ fb58e0db
  + engines/strata/xxs-20261016/patches/c4-to-xxs-20261016.patch   （平台与内核累计工作）
  + sources/xxs-20261016-gold/patches/patch_yf16_*.py              （GEMM_Y_F16，按 manifest 顺序）
  = 引擎 43002a72…
```

注意：补丁链应用后重编译**不保证**得到逐字节相同的二进制（编译器、DTK 版本、构建目录都会影响）；字节级身份请用 `manifest.json` 里的 `engine_sha256` 核对发布包，而不是核对重编译产物。
