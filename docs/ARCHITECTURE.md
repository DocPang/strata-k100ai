# 引擎、模型与拓扑分别版本化

此仓库负责分发安装方法、运行包身份、配置与验证资料，不复制全部研究目录，也不把所有推理后端强行塞进同一源码树。

## 新增模型配置

1. 在 `profiles/<model>-<quant>-<topology>/` 新建独立 profile/settings。
2. 记录模型来源、文件哈希、pack 生成方式、MTP 输入和格式覆盖。
3. 明确复用哪个 engine。相同引擎不代表相同内核命中或收益。
4. 添加模型加载、数值、长上下文、缓存和固定负载测试记录。
5. 将通过测试的 profile 加入安装入口和兼容表，发布新 kit 版本。

## 新增引擎或 TP2

引擎放在 `engines/<backend>/<version>/`，内容至少包括 artifact SHA-256、基础镜像约束、源码来源、构建方式和验证状态。镜像入口放在 `containers/<backend>/`。

TP2 作为独立拓扑提供设备列表、通信依赖、内存要求和启动文件，例如专门的 Compose；必须重新验证通信路径、数值与性能。单卡的“两个独立副本”不称为 TP2。若 TP2 使用其他推理框架，新增后端目录，不复用错误的 Strata 参数。

Kit 标签（例如 v0.1.0-rc.2）固定安装脚本和配置组合；引擎 ID（strata/c4）固定具体二进制和源码配方；模型权重通过独立来源与哈希固定。更新其中一项不覆盖历史资产。

## 分发边界

Git 保存代码、文档、小配置和补丁；Release 保存运行包和部署包；权重和 native pack 单独存储。运行包不包含供应商库，基础镜像由用户取得。以后需要发布成品镜像时，也要保留这条本地组合安装路线。
